# 卓球フィードバックノート

**▶ アプリを開く：https://askedkazu.github.io/tt-feedback-note/**

練習の動画をAIに見てもらい、フォームのフィードバックと振り返りの助言をもらう、自分用の卓球ノートです。
HTML / CSS / JavaScript だけで動き、ビルドは不要です。「ちょいステップ習慣」と同じ Firebase プロジェクトを使います。

## 使い方

部活中はスマホが使えないので、**部活のあとの振り返り**がメイン。

- ホームの「振り返りを書く」→ うまくいかなかったこと・感じたことを書く → 「AIに助言をもらう」→ 記録する
  - 今日練習した技を3つまで選べる（選ばなければ「練習全体」）。同じ技の最近の記録も踏まえて助言する
  - 助言の「次の練習で意識すること」は、練習中に頭の中で思い出せる短い合言葉にする。ホームの「📌 次の練習で意識すること」に出るので、部活の前に見ておける

動画でフォームを見てもらうとき（家での素振り・部活以外の練習）は「🎥 動画でフォームチェック」から：

1. 今日の技と、意識するポイント（1〜2個）を選ぶ
2. 練習して、動画を撮る（または選ぶ）。打っている場面で一時停止して「ここから」を押し、AIに見せる範囲（2・3・5秒）を決める
3. 「AIにフィードバックしてもらう」→ フォーム点・良かった点・直す点（優先順）・チェック項目の ◎○△（部活中はスマホが使えないので、練習メニューは出さない）
4. 振り返りを書くと、AIが原因と対策を助言（同じ技の最近の記録も踏まえる）→ 記録する
5. 記録の詳細で「☆ ベストにする」と、次からその技はベストの回と比べたフィードバックになる

## ボールの軌道を3Dで見る

図鑑の技を開き「🎥 ボールの軌道を3Dで見る」を押すと、その技の打球を3Dで再生する（フットワークの技以外の15技）。

- スロー再生（1/4・1/2・等速）、視点（後ろ・横・上・相手側）、指で回転・拡大
- 点線は「回転がなかったらこう飛ぶ」軌道。回転でどれだけ落ちる・曲がるかが比べられる
- 「🎬 動画として保存」で、1回分の再生を動画ファイル（mp4 または webm）にして保存
- 軌道は `physics.js` で計算している：重力・空気抵抗・マグヌス力（回転で曲がる力）と、台でのバウンド（摩擦で回転が変わる）。
  技ごとの打球（打つ位置・初速・回転・狙う場所）は `physics.js` の `SHOTS`。打ち出す角度は、狙った場所に落ちるように自動で計算する
- 3D表示は three.js（CDN）を使い、ボタンを押したときだけ読み込む（`trajectory-view.js`）

### 利き手

- 設定タブの「利き手」（最初は左利き）に合わせて、3Dの選手・ラケット・軌道を左右反転して表示する。
  計算は右利きで行い、表示するときに横方向を反転する（物理は左右対称なので、横回転の曲がる向きも正しく反対になる）
- 図鑑の説明（右足・左足など）は右利きで書いてあり、左利きのときは「右」「左」を入れかえて表示する。AIに送る技の要点も同じ

### 選手（関節で決める動き）

- 3Dの画面には選手（棒人間）が出て、技ごとにスイングする。動きは `trajectory-view.js` の `FORMS` で、技ごとに
  「構え・引き・打球・振り抜き」の姿勢を**関節の角度**で決めている（体のひねり・前傾・沈み込み・重心・上腕の向き・前腕の向き・手首・前腕のひねり）。
  その間はなめらかな曲線でつなぎ、引きはゆっくり、打球でいちばん速く、振り抜いて止まり、構えに戻る
- 姿勢は卓球レポート（バタフライ）「ようこそ卓球 基本技術編」①〜⑦と「基本のバックハンド」の連続写真を参考にした
  （フォアロング・バック打ち・フォアドライブ・バックドライブ・下回転サーブ・バックツッツキ・フォアツッツキ）
- 打つ瞬間は自動で合わせる：
  1. 前腕のひねりと手首の曲げで、ラケット面を物理計算の向きにぴったり合わせる（手首の曲げが小さく済む前腕の向きを選ぶ）
  2. 上腕の角度とひざの曲げで、ラケットの高さをボールに合わせ、体ごと動かして位置を合わせる
  3. 引きと振り抜きの関節の角度を少しずつ調整して、ラケットの動く向きを物理計算の振る向きにそろえる
- 技と形の対応は `FORM_BY_TECH`。スマホのスイングは、打球の回転からドライブ／ロングの形を選ぶ
- ラケットはシェークハンドで握る（手のひら・親指・人差し指・グリップに巻きつく3本の指。サーブは3本の指をグリップから離す）
- 視点「持ち方」：ラケットを持つ手を追いかけて、振っている間の手首とラケットの角度を見せる
- 視点「インパクト」：打つ瞬間を拡大して超スローにする。体は半透明になり、振る向き（オレンジの矢印）と
  ボールの回転の向き（水色の矢印）が見える。画面の下に「ラケット面：かぶせる 12°」「スイング：上へ 60°」などを表示

## スマホでスイング（`swing.js`）

ホームの「📱 スマホでスイング」から。スマホの画面をラケットの面にして素振りすると、センサーでスイングを測って判定する。

- 速さ：ジャイロの回転の速さ × 0.5m（腕＋ラケット）
- 振る向き：速く振っている間の加速度のうち、上向きの割合
- ラケット面：いちばん速い瞬間の画面の向き（`deviceorientation` の beta・gamma から）
- はじめに1回、画面を上にして平らに持って、加速度の向き（端末によって符号が逆）を合わせる
- 測ったスイングから打球の速さと回転を作り、打ち出し角度のずれが ±12° 以内なら「IN!」。外ならネット／オーバーなど。
  入る角度の範囲は物理計算で求め、その中／外に当てはめて3Dでも再生できる
- 回数・IN率・連続IN・最高速度はこの端末に保存。iPhone は「センサーを使う」を押したときに許可が必要

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | 画面（Tailwind CSS を CDN で読み込み） |
| `style.css` | 共通部品の見た目 |
| `app.js` | 画面の切り替え、動画からの写真の切り出し、AI呼び出し、記録・グラフ・バッジ、ログイン |
| `physics.js` | ボールの軌道の計算と、技ごとの打球の例 |
| `trajectory-view.js` | 軌道を3Dで見る画面（three.js）。選手・ラケット・インパクトの表示 |
| `swing.js` | スマホをラケットにして素振りする画面 |
| `techniques.js` | 技の図鑑（コツ・よくあるミス・チェック項目・撮り方。drills は今は表示していない）。技を足すときはここに追加 |
| `firebase-config.js` | Firebase の設定（ちょいステップ習慣と同じ） |
| `manifest.webmanifest`, `icons/` | ホーム画面に追加したときのアプリ名・アイコン |

## AIに送るもの（`app.js` の `requestFeedback` / `requestAdvice`）

- 動画そのものは送らない。選んだ範囲を等間隔に16枚（5秒のときは20枚）、長辺512pxの JPEG に切り出して送る
  （Gemini は動画を1秒に1コマしか見ないため、速いスイングは写真で送った方が細かく見られる）
- 一緒に送る：プロフィール（利き手・グリップ・ラバー・戦型・レベル・目標）、技の要点とよくあるミス、意識したこと、
  ベストの回と比べるときはその回の写真10枚
- モデルは `gemini-3.8-flash` → だめなら `gemini-3.5-flash-lite`（Firebase AI Logic 経由。APIキーは不要）
- 返事は `responseSchema` で形を決めている。チェック項目の ◎○△ を 3・2・1 点として平均し、100点満点の「フォーム点」にする

## データの保存（Firestore）

| 場所 | 中身 |
| --- | --- |
| `tt_users/{uid}` | プロフィール、技ごとのベストの回 |
| `tt_users/{uid}/sessions/{id}` | 記録（技〔`techIds`：振り返りは複数、`techId`：その1つ目〕・意識したこと・フィードバック・フォーム点・振り返り・助言・小さなサムネイル） |
| `tt_users/{uid}/frames/{id}` | 記録ごとの連続写真（長辺360px）。記録を開いたときとベストと比べるときだけ読む |

- ログインしていないときは、記録はこの端末（localStorage）だけに保存し、写真は保存しない。あとでログインするとアカウントに送る

## 最初の設定（1回だけ）

### 1. GitHub Pages で公開する

GitHub のこのリポジトリ → **Settings** → **Pages** →「Build and deployment」の Source を **Deploy from a branch**、
Branch を **main** / **/(root)** にして **Save**。数分で https://askedkazu.github.io/tt-feedback-note/ が開けるようになる。

### 2. Firestore のルールに `tt_users` を追加する

Firebase コンソール → Firestore Database → **ルール** に、`match /tt_users/...` の部分を足して「公開」
（`管理者のUID` は今のルールに書いてある値のまま）：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAdmin() {
      return request.auth != null && request.auth.uid == "管理者のUID";
    }
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
      allow read: if isAdmin();
    }
    match /photos/{id} {
      allow create: if request.auth != null && request.resource.data.uid == request.auth.uid;
      allow read, delete: if isAdmin();
    }
    // 卓球フィードバックノート（本人だけが読み書きできる）
    match /tt_users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

ログイン（承認済みドメイン `askedkazu.github.io`）と App Check（reCAPTCHA のドメイン）は、
ちょいステップ習慣と同じドメインなので追加の設定は不要。
